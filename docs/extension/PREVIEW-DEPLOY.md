# نشر نسخة معاينة على خادم Linux

الغرض: نسخة واحدة من «مدار» على خادمك، تُبنى من فرع العمل، لتراها وتنقر فيها. ليست نسخة إنتاج.

**حالة هذه التعليمات:** مكتوبة من أدوات النشر الموجودة في المشروع الأصلي (`deploy/docker`)، وهدف Compose نفسه يُختبر في CI على كل دفعة. لم أنفّذها أنا على خادم، لأن بيئة العمل بلا Docker. الخطوة 6 (بيانات الجهة التجريبية) تنتظر جلسة البذرة في خطة الشريحة، ومكانها محجوز أدناه.

## 1. ما تحتاجه

| البند | القيمة |
|---|---|
| النظام | Linux حديث (Ubuntu 22.04 أو 24.04 مثلاً) |
| العتاد | 2 نواة، 4 GB ذاكرة، 20 GB قرص. **بناء الصورة يحتاج الـ4 GB كاملة** |
| البرامج | `git`، Docker مع إضافة Compose |
| المنافذ | 80 و443 مفتوحان، أو منفذ آخر تختاره |
| اسم نطاق | اختياري. به تصدر شهادة HTTPS تلقائياً. دونه تعمل النسخة على HTTP |
| صلاحية المستودع | المستودع خاص، فالخادم يحتاج مفتاح نشر (deploy key) للقراءة فقط |

لا يلزم بريد ولا مزوّد ذكاء اصطناعي. المعاينة في معلَمها الأول تعمل بمخرجات وكيل ثابتة.

## 2. جلب الكود

```bash
git clone git@github.com:malkhana10-coder/open-okr.git madar-preview
```

```bash
cd madar-preview && git checkout claude/awesome-gates-rztn32
```

## 3. بناء الصورة

من جذر المستودع. البناء الأول يأخذ عدة دقائق.

```bash
docker build -f deploy/docker/Dockerfile -t madar:preview .
```

## 4. التشغيل

باسم نطاق (HTTPS تلقائي):

```bash
cd deploy/docker && OPENOKR_IMAGE=madar:preview OPENOKR_DOMAIN=preview.example.com ./openokr up
```

دون اسم نطاق، على منفذ تختاره:

```bash
cd deploy/docker && OPENOKR_IMAGE=madar:preview OPENOKR_HTTP_PORT=8080 OPENOKR_HTTPS_PORT=8443 ./openokr up
```

الأمر يولّد كل الأسرار في `deploy/docker/secrets/` عند أول تشغيل، ويشغّل الترحيلات (مجرى الأصل ثم مجرى الامتداد)، ويطبع رابط الإعداد و**رمز الإعداد**.

## 5. إنشاء حساب المالك

1. افتح الرابط المطبوع فور انتهاء التشغيل.
2. أدخل رمز الإعداد. إن فاتك: `grep OPENOKR_SETUP_CODE deploy/docker/secrets/app.env`.
3. أنشئ حساب المالك، وسمِّ مساحة العمل «الجهة الحكومية التجريبية».
4. من الإعدادات العامة اختر العربية لغةً لمساحة العمل.

دون الرمز لا يستطيع أحد إنشاء حساب المالك، فمعرفة العنوان وحدها لا تكفي للاستيلاء على النسخة.

## 6. بيانات الجهة التجريبية

**ينتظر جلسة البذرة (الجلسة 6 في القسم 9أ من [`design/b0-vertical-slice.md`](design/b0-vertical-slice.md)).** سيكون أمراً واحداً يُنشئ القطاع والمستخدمَين بالدورين (مكتب الاستراتيجية، القيادة) ويرفع الوثيقة التجريبية. أكتب الأمر هنا في الالتزام نفسه الذي يضيفه.

## 7. التحديث بعد دفعات جديدة

```bash
cd madar-preview && git pull
```

```bash
docker build -f deploy/docker/Dockerfile -t madar:preview .
```

```bash
cd deploy/docker && OPENOKR_IMAGE=madar:preview ./openokr up
```

البيانات تبقى، والصورة الجديدة تشغّل الترحيلات الجديدة عند إقلاعها. أعد كتابة `OPENOKR_DOMAIN` أو المنافذ كما في الخطوة 4.

## 8. أوامر يومية

| الأمر (من `deploy/docker`) | ما يفعله |
|---|---|
| `./openokr status` | حالة الحاويات وما ينتظر من تغييرات البيانات |
| `./openokr logs` | السجلات |
| `./openokr backup` | نسخة احتياطية |
| `./openokr down` | إيقاف مع بقاء البيانات |
| `./openokr destroy` | **حذف النسخة وبياناتها.** لا رجعة فيه |

## 9. تنبيهات قبل أن يراها غيرك

- **لا ترفع عليها وثائق حقيقية.** النسخة للمعاينة، وخادم المعاينة ليس بيئة معتمدة لبيانات جهة.
- **الرخصة:** الكود AGPL-3.0، وإتاحة النسخة عبر الشبكة لغيرك تلزم بإتاحة الكود المصدري المعدَّل لهم. سؤال الرخصة مؤجل لمستشارك القانوني، فأبقِ المعاينة لك ولفريقك حتى يُحسم.
- **التسجيل مغلق بعد حساب المالك.** الأعضاء يدخلون بدعوة.
- إن وضعت النسخة خلف وكيل عكسي آخر أو CDN، فاقرأ `docs/install/behind-a-proxy.md` قبل التشغيل، وإلا تشاركت حدود محاولات الدخول بين كل الزوار.

## 10. إن لم تعمل

| ما تراه | السبب والحل |
|---|---|
| «address already in use» | شيء آخر على المنفذ 80 أو 443. استخدم صيغة المنافذ في الخطوة 4 |
| البناء يتوقف أو يُقتل | الذاكرة أقل من 4 GB. أضف swap أو ابنِ على جهاز آخر وانقل الصورة بـ`docker save` و`docker load` |
| «That setup code is not right» | اقرأ الرمز من `secrets/app.env` ثانية |
| الشهادة لا تصدر | اسم النطاق لا يشير للخادم بعد، أو المنفذان 80 و443 غير مفتوحين من الخارج |

المرجع الكامل بالإنجليزية: `docs/install/compose.md`.
