# نشر نسخة معاينة على خادم Linux

الغرض: نسخة واحدة من «مدار» على خادمك، تُبنى من فرع العمل، لتراها وتنقر فيها. ليست نسخة إنتاج.

**حالة هذه التعليمات:** مكتوبة من أدوات النشر الموجودة في المشروع الأصلي (`deploy/docker`)، وهدف Compose نفسه يُختبر في CI على كل دفعة. لم أنفّذها أنا على خادم، لأن بيئة العمل بلا Docker. الخطوة 6 (بيانات الجهة التجريبية) جُرّب أمرها محلياً دون Docker، كما تقول في آخرها.

## 1. ما تحتاجه

| البند | القيمة |
|---|---|
| النظام | Linux حديث (Ubuntu 22.04 أو 24.04 مثلاً) |
| العتاد | 2 نواة، 4 GB ذاكرة، 20 GB قرص. **بناء الصورة يحتاج الـ4 GB كاملة** |
| البرامج | `git`، Docker مع إضافة Compose. وللخطوة 6: Node 22 و pnpm (`corepack enable`) |
| المنافذ | 80 و443 مفتوحان، أو منفذ آخر تختاره |
| اسم نطاق | اختياري. به تصدر شهادة HTTPS تلقائياً. دونه تعمل النسخة على HTTP |
| صلاحية المستودع | المستودع خاص، فالخادم يحتاج مفتاح نشر (deploy key) للقراءة فقط |

لا يلزم بريد ولا مزوّد ذكاء اصطناعي. المعاينة في معلَمها الأول تعمل بمخرجات وكيل ثابتة.

## 2. جلب الكود

```bash
git clone git@github.com:malkhana10-coder/open-okr.git madar-preview
```

```bash
cd madar-preview && git checkout claude/awesome-gates-rztn32
```

## 3. بناء الصورة

من جذر المستودع. البناء الأول يأخذ عدة دقائق.

```bash
docker build -f deploy/docker/Dockerfile -t madar:preview .
```

## 4. التشغيل

شغّل النسخة مع ملف Compose الإضافي الذي ينشر قاعدة البيانات على `127.0.0.1` فقط. أمر البذرة في الخطوة 6 يعمل من هذه النسخة من الكود على الخادم، فيحتاج الوصول إلى القاعدة. المنفذ لا يُفتح للخارج.

```bash
export COMPOSE_FILE="compose.yaml:../staging/compose.staging.yaml"
```

باسم نطاق (HTTPS تلقائي):

```bash
cd deploy/docker && OPENOKR_IMAGE=madar:preview OPENOKR_DOMAIN=preview.example.com ./openokr up
```

دون اسم نطاق، على منفذ تختاره:

```bash
cd deploy/docker && OPENOKR_IMAGE=madar:preview OPENOKR_HTTP_PORT=8080 OPENOKR_HTTPS_PORT=8443 ./openokr up
```

الأمر يولّد كل الأسرار في `deploy/docker/secrets/` عند أول تشغيل، ويشغّل الترحيلات (مجرى الأصل ثم مجرى الامتداد)، ويطبع رابط الإعداد و**رمز الإعداد**.

**أبقِ `COMPOSE_FILE` مضبوطاً في كل أمر `./openokr` لاحق** (الخطوتان 7 و8)، وإلا أُعيد إنشاء الحاوية دون المنفذ.

## 5. إنشاء حساب المالك

1. افتح الرابط المطبوع فور انتهاء التشغيل.
2. أدخل رمز الإعداد. إن فاتك: `grep OPENOKR_SETUP_CODE deploy/docker/secrets/app.env`.
3. أنشئ حساب المالك، وسمِّ مساحة العمل «الجهة الحكومية التجريبية».
4. من الإعدادات العامة اختر العربية لغةً لمساحة العمل.

دون الرمز لا يستطيع أحد إنشاء حساب المالك، فمعرفة العنوان وحدها لا تكفي للاستيلاء على النسخة.

## 6. بيانات الجهة التجريبية

بعد الخطوة 5، ومساحة العمل ما زالت فارغة. البذرة تعمل من الكود على الخادم لا من داخل الصورة، فتحتاج Node 22 و pnpm مرة واحدة:

```bash
corepack enable
```

```bash
pnpm install
```

ثم من جذر المستودع:

```bash
sh deploy/extension/seed-trial-entity.sh
```

يأخذ أقل من دقيقة. يطبع في أوله **كلمة مرور عشوائية واحدة للمستخدمين الخمسة**، وفي آخره عناوين دخولهم. احفظ الكلمة: لا تُخزَّن في مكان. لتختارها أنت (12 حرفاً على الأقل، ولا تستعمل كلمة مكتوبة في أي وثيقة). الكلمة التي تكتبها في السطر تبقى في سجل أوامر الطرفية:

```bash
sh deploy/extension/seed-trial-entity.sh --password '<كلمة مرور من اختيارك>'
```

| ما تنشئه البذرة | العدد |
|---|---|
| القطاعات والوكالات | 3 و7 |
| المجالات | 5 |
| الدورتان السنويتان 2026 و2027، وكلتاهما في طور التخطيط (لا أهداف في 2026، فيها القراءات فقط) | 2 |
| الأهداف: قطاعية وتشغيلية، بتصنيفها ومصدرها | 5 و2 |
| المؤشرات، منها 5 تشغيلية على الوكالات | 14 |
| قراءات 2026 من يناير إلى أكتوبر | 68 |
| المبادرات | 15 |
| المستخدمون | 5 |

| عنوان الدخول | الدور | ما يستطيعه |
|---|---|---|
| `strategy@tajriba.example` | مكتب الاستراتيجية | يصوغ ويرفع للاعتماد في القطاعات الثلاثة |
| `leadership@tajriba.example` | القيادة | يعتمد ويعيد، ويعلّق. لا يكتب |
| `pmo@tajriba.example` | مكتب إدارة المشاريع | دور «عضو» حتى تُصمَّم صلاحياته في المرحلة (ج) |
| `licensing@tajriba.example` | مالك عمل (وكالة التراخيص) | عضو في وكالة التراخيص ومسؤول قطاعها |
| `performance@tajriba.example` | فريق الأداء | دور «عضو» حتى المرحلة (ج) |

النطاق `tajriba.example` محجوز (RFC 2606) ولا يستقبل بريداً. حسابك أنت، المالك، يعتمد أيضاً.

**البذرة تُشغَّل مرة واحدة، وفي مساحة عمل لا يعمل فيها أحد.** ترفض مساحة فيها عضو غير مالكها، أو قطاع، أو مؤشر، وترفض نسخة فيها حساب بأحد العناوين الخمسة. إن توقفت في منتصفها أو أردت البدء من جديد: `./openokr destroy` ثم الخطوات 4 إلى 6. الوثيقتان التجريبيتان لا تُبذران: رفعهما أول خطوة في العرض (الخطوة 6أ).

**حالة هذه الخطوة:** الأمر `pnpm ext:seed` نفسه جُرّب على قاعدة محلية جديدة ونجح، ورُفض تشغيله الثاني. السكربت الذي يقرأ أسرار Compose منسوخ عن سكربت المشروع الأصلي لنسخ الاختبار (`deploy/staging/seed.sh`) ولم أجرّبه على Docker.

## 6أ. الوثيقتان التجريبيتان

العرض يبدأ برفع وثيقة، فالوثيقتان ملفان ترفعهما أنت من شاشة الوثائق لا بيانات مبذورة. هما في المستودع:

| الملف | يُرفع على |
|---|---|
| `packages/core/src/extension/trial-entity/documents/licensing-compliance.pdf` | قطاع الخدمات والتراخيص |
| `packages/core/src/extension/trial-entity/documents/digital-transformation.pdf` | قطاع التخطيط والتطوير |

كل منهما 13 صفحة خيالية، فيها ستة أهداف وعشر مبادرات مقترحة. انسخهما إلى حاسوبك وارفعهما بحساب مكتب الاستراتيجية. سمِّهما بما تشاء: مخرجات الوكيل التجريبية تتعرف على الوثيقة من صفحتها الأولى لا من الاسم.

الرفع من «التخطيط» في الشريط الجانبي: اختر القطاع، ثم «رفع وثيقة». القراءة تتم في الخلفية خلال ثوانٍ، فأعد تحميل الصفحة لترى عدد الصفحات، ثم «اقرأ» لتتصفح نص كل صفحة كما قرأه النظام.

## 7. التحديث بعد دفعات جديدة

```bash
cd madar-preview && git pull
```

```bash
docker build -f deploy/docker/Dockerfile -t madar:preview .
```

```bash
cd deploy/docker && OPENOKR_IMAGE=madar:preview ./openokr up
```

البيانات تبقى، والصورة الجديدة تشغّل الترحيلات الجديدة عند إقلاعها. أعد كتابة `OPENOKR_DOMAIN` أو المنافذ كما في الخطوة 4.

## 8. أوامر يومية

| الأمر (من `deploy/docker`) | ما يفعله |
|---|---|
| `./openokr status` | حالة الحاويات وما ينتظر من تغييرات البيانات |
| `./openokr logs` | السجلات |
| `./openokr backup` | نسخة احتياطية |
| `./openokr down` | إيقاف مع بقاء البيانات |
| `./openokr destroy` | **حذف النسخة وبياناتها.** لا رجعة فيه |

## 9. تنبيهات قبل أن يراها غيرك

- **لا ترفع عليها وثائق حقيقية.** النسخة للمعاينة، وخادم المعاينة ليس بيئة معتمدة لبيانات جهة.
- **الرخصة:** الكود AGPL-3.0، وإتاحة النسخة عبر الشبكة لغيرك تلزم بإتاحة الكود المصدري المعدَّل لهم. سؤال الرخصة مؤجل لمستشارك القانوني، فأبقِ المعاينة لك ولفريقك حتى يُحسم.
- **التسجيل مغلق بعد حساب المالك.** الأعضاء يدخلون بدعوة.
- إن وضعت النسخة خلف وكيل عكسي آخر أو CDN، فاقرأ `docs/install/behind-a-proxy.md` قبل التشغيل، وإلا تشاركت حدود محاولات الدخول بين كل الزوار.

## 10. إن لم تعمل

| ما تراه | السبب والحل |
|---|---|
| «address already in use» | شيء آخر على المنفذ 80 أو 443. استخدم صيغة المنافذ في الخطوة 4 |
| البناء يتوقف أو يُقتل | الذاكرة أقل من 4 GB. أضف swap أو ابنِ على جهاز آخر وانقل الصورة بـ`docker save` و`docker load` |
| «That setup code is not right» | اقرأ الرمز من `secrets/app.env` ثانية |
| الشهادة لا تصدر | اسم النطاق لا يشير للخادم بعد، أو المنفذان 80 و443 غير مفتوحين من الخارج |

المرجع الكامل بالإنجليزية: `docs/install/compose.md`.
